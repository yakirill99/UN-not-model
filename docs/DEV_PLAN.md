## 1. Как пользоваться этим файлом

- Это **план исполнения**, а `ROADMAP.md` — **обоснование и справочник**. Если что-то не расписано здесь, смотри соответствующий раздел роадмапа.
- Спринты идут строго по порядку: каждый опирается на результат предыдущего.
- У каждого спринта есть **критерий готовности**. Пока он не выполнен, следующий спринт не начинается.
- В конце файла — **журнал прогресса**. Обновляй его после каждого спринта и прикладывай файл к новому диалогу: так контекст не теряется.

## 2. Контекст проекта за одну минуту

**Что делаем.** Веб-версию пошаговой многопользовательской стратегии «Мировая Арена» на тему ООН. Исходник — настольно-цифровая игра «Немодель ООН в Смольном» (polymun.spb): 5 стран по 4 города, 6 раундов, дебаты и переговоры вживую, приказы — тайно, подсчёт — координаторами в Google-таблицах. Мы заменяем координаторов сервером.

**Зачем.** Учебное задание в Политехе + портфолио под fullstack, DevOps/SRE, аналитику, ML/DS и LLM-инженерию.

**Главная архитектурная идея.** Правила будут меняться после каждой реальной игры (v1 → v2 → v3), поэтому движок — это конвейер систем, собранный по версионированному YAML-конфигу, а любой игрок (человек, бот, RL, LLM) работает через один интерфейс `Agent`.

**Документы проекта:**

| Файл | Что внутри |
|---|---|
| `DEV_PLAN.md` | Этот план: спринты до v1.0 |
| `ROADMAP.md` | Стек, архитектура, K8s, тестирование, все этапы 0–14 |
| `GAME_RULES.md` | Правила v1.0 — **реализуем в первую очередь** |
| `GAME_RULES_2.md` | v2: устойчивость, рейтинг, ООН, события, технологии (после v1.0) |
| `GAME_RULES_3.md` | v3: отраслевая экономика и кризисы (после v2) |

## 3. Зафиксированные решения

| Тема | Решение |
|---|---|
| Бэкенд | Python 3.13 + FastAPI + Pydantic v2 + SQLAlchemy 2.0 (async) + Alembic + asyncpg |
| База | PostgreSQL |
| Фронтенд | React + TypeScript + Vite + TanStack Query + Tailwind + shadcn/ui |
| Инструменты | uv, ruff, mypy, pytest, hypothesis, pnpm, just, mise, pre-commit |
| Упаковка | Один образ: бэкенд + собранный фронтенд + `rules/` |
| Запуск | Docker Compose (`just up`); Kubernetes (k3d/k3s) — после v1.0 |
| Движок | Конвейер систем, `RuleSet` из YAML с `extends`, детерминированный RNG, `Observation`/`ActionSpace`, headless runner |
| Правила v1.0 | `GAME_RULES.md` + решения из его раздела 17 (таблица противоречий) |
| Числа | Проценты и деньги — целые: развитие `65` = 65%. Уровень жизни — целое в сотых долях процента: `5445` = 54,45% |
| Стартовые условия | Отделены от правил: **сценарии** `scenarios/*.yaml` (см. спринт 1) |
| Аутентификация | Коды команд от ведущего → подписанный JWT в httpOnly cookie |
| Хост разработки | Windows + WSL2 + Docker Desktop (все команды — внутри WSL2) |

### Новое решение: правила и сценарии раздельно

В роадмапе стартовые условия жили внутри правил. Удобнее разделить:

- **`rules/vX.yaml`** — как устроен мир: цены, эффекты, лимиты, формулы, порядок обработки.
- **`scenarios/*.yaml`** — с чего начинается партия: страны, города, стартовое развитие, бюджеты.

Тогда одни и те же правила можно играть на «историческом» старте из Смольного и на «равном» старте, а в симуляциях — на случайных стартах.

## 4. Окружение разработчика

### Установка (один раз)

1. **WSL2** с Ubuntu (`wsl --install` в PowerShell от администратора), дальше вся работа — внутри WSL2.
2. **Docker Desktop** с включённой интеграцией WSL2.
3. **VS Code** + расширения: Remote – WSL, Python, Pylance, Ruff, ESLint, Tailwind CSS IntelliSense, Even Better TOML, YAML.
4. Внутри WSL2: `git`, затем **mise** (`curl https://mise.run | sh`) — он поставит остальное по `mise.toml`.
5. Репозиторий держи **внутри файловой системы WSL2** (`~/projects/world-arena`), а не на `/mnt/c/...`: иначе Docker и файловые наблюдатели работают в разы медленнее.

### Версии инструментов (`mise.toml`)

```toml
[tools]
python = "3.13"
uv = "latest"
node = "22"
pnpm = "latest"
just = "latest"
```

Версии `latest` на старте нормальны; после первого `mise install` закрепи конкретные версии, которые установились.

### Проверка окружения

```bash
docker run --rm hello-world
mise install
python --version && uv --version && node --version && pnpm --version && just --version
```

## 7. Спринт 1. Ядро движка

**Цель:** раунд считается по правилам из YAML через конвейер систем. В этом спринте — каркас и 3–4 простые системы, остальные в спринте 2.

### Файлы и ответственность

```text
backend/arena/engine/
├── state.py        # модели состояния
├── rules.py        # RuleSet, загрузка YAML, extends, overrides, JSON Schema
├── scenario.py     # загрузка сценария → начальный GameState
├── orders.py       # модели приказов страны и OrderBook раунда
├── events.py       # события (discriminated union), schema_version
├── rng.py          # RngFactory
├── pipeline.py     # реестр систем, build_pipeline, resolve_round
└── systems/
    ├── __init__.py # регистрация систем
    ├── base.py     # протокол System, декоратор @register
    ├── budget.py
    ├── develop.py  # инвестиции и экопрограмма
    ├── life_level.py
    └── income.py
```

### Модели состояния (`state.py`)

```python
class City(BaseModel):
    id: str                      # "moscow"
    name: str                    # "Москва"
    development: int             # в процентах: 65
    shield: bool = False
    destroyed: bool = False
    life_level: int = 0          # в сотых долях процента: 5445 = 54,45%

class Country(BaseModel):
    id: str                      # "russia"
    name: str
    budget: int
    cities: list[City]
    nuclear_tech: bool = False
    bombs: int = 0               # готовые к применению
    bombs_pending: int = 0       # произведены в этом раунде, доступны со следующего
    laugh: int = 0               # коэффициент смеха, п.п.
    aid_pending: int = 0         # полученная помощь, доступна со следующего раунда
    sanctioned_by: list[str] = []

class GameState(BaseModel):
    round: int                   # 1..rounds
    ecology: int                 # 0..100
    countries: list[Country]
    modules: dict[str, dict] = {}    # состояние модулей v2/v3, в v1 пусто
    state_schema_version: int = 1
```

### Приказы (`orders.py`)

```python
class CountryOrders(BaseModel):
    invest: list[str] = []          # id своих городов (повтор = несколько инвестиций)
    eco_programs: int = 0
    nuclear_tech: bool = False
    bombs: int = 0
    strikes: list[str] = []         # id чужих городов
    shields: list[str] = []         # id своих городов
    sanctions: list[str] = []       # id стран
    aid: dict[str, int] = {}        # id страны → сумма

class HostInput(BaseModel):
    laugh_winner: str | None = None # id страны, выбранной ведущим

class OrderBook(BaseModel):
    orders: dict[str, CountryOrders]   # id страны → приказы
    host: HostInput = HostInput()
```

### Черновик `rules/v1.0.yaml`

```yaml
version: "1.0.0"
extends: null
modules: [core]

pipeline:
  - budget          # проверка и списание по приоритетам, отклонённое → события
  - aid             # переводы (в aid_pending получателя)
  - build           # ядерная технология, щиты, производство бомб
  - develop         # инвестиции и экопрограммы
  - strikes         # удары с учётом щитов
  - sanctions
  - clamp           # экология 0..100, развитие ≥ 0
  - life_level
  - income
  - laugh
  - end_of_round    # bombs_pending → bombs, aid_pending → budget, сброс санкций

params:
  rounds: 6
  ecology: {min: 0, max: 100}
  life_weights: {development: 33, ecology: 33, laugh: 33}   # УЖ×100 = Σ вес × показатель
  income: {k_development: 100, k_ecology: 150}              # доход = (k_d×dev + k_e×eco) / 100
  laugh_bonus: 20
  budget_priority: [shield, invest, eco_program, nuclear_tech, bomb, aid]

actions:
  invest:
    cost: 150
    effect: {development: 15}
    target: own_city
    max_per_city_per_round: null          # раздел 17, решение 6: без ограничения
    ui: {title: "Инвестировать в развитие города", emoji: "🌆"}
  eco_program:
    cost: 200
    effect: {ecology: 30}
    ui: {title: "Запустить экологическую программу", emoji: "♻️"}
  nuclear_tech:
    cost: 500
    effect: {ecology: -5}
    once_per_game: true
    ui: {title: "Разработать ядерную технологию", emoji: "☢️"}
  bomb:
    cost: 150
    effect: {ecology: -5}
    requires: nuclear_tech
    max_per_round: 3
    usable: next_round
    ui: {title: "Произвести ядерные бомбы", emoji: "💣"}
  strike:
    cost: 0
    effect: {ecology: -5}
    requires: bomb
    max_per_round: 3
    max_per_target_city_per_round: 1
    anonymous: true
    ui: {title: "Нанести ядерный удар", emoji: "🚀"}
  shield:
    cost: 300
    target: own_city
    active: same_round
    ui: {title: "Построить ядерный щит", emoji: "🛡️"}
  sanction:
    cost: 0
    effect: {development_all_cities: -5}
    duration_rounds: 1
    visible_to_target: true
    ui: {title: "Наложить экономические санкции", emoji: "❌"}
  aid:
    min_amount: 1
    available: next_round
    ui: {title: "Материальная помощь", emoji: "💸"}
```

### Конвейер (`pipeline.py`) и RNG (`rng.py`)

Реализовать по разделам 3.1 и 3.4 `ROADMAP.md`:
- `@register("budget")` добавляет класс в реестр;
- `build_pipeline(rules)` падает с понятной ошибкой, если в `pipeline` есть незарегистрированная система;
- `resolve_round(state, orders, rules, seed)` копирует состояние, прогоняет системы, возвращает `(new_state, events)`;
- `RngFactory(game_seed, round).for_system(system_id)`.

### События (`events.py`)

Базовый класс с полями `type`, `schema_version`, `round`, `actor`, `target`, и первые события: `OrderRejected`, `BudgetSpent`, `CityInvested`, `EcologyChanged`, `LifeLevelComputed`, `IncomeCredited`.

## 8. Спринт 2. Полный движок v1.0 и реплей Смольного

**Цель:** все правила v1.0, наблюдения и действия, headless runner, и главная проверка — реплей реальной партии.

### Задачи

**Системы** (по порядку обработки раздела 12 `GAME_RULES.md`):

| Система | Суть и крайние случаи |
|---|---|
| `budget` | Полная стоимость приказа; при нехватке денег — исполнение по `budget_priority`, остальное → `OrderRejected` с причиной |
| `aid` | Перевод в `aid_pending` получателя; нельзя себе; нельзя больше бюджета |
| `build` | Технология (разово), щиты на свои неуничтоженные города, бомбы (нужна технология, ≤ 3, в `bombs_pending`) |
| `develop` | Инвестиции только в свои неуничтоженные города |
| `strikes` | ≤ 3 за раунд; нужны бомбы на складе; ≤ 1 удара одной страны по городу; по своему — нельзя; щит поглощает один удар; два удара по городу со щитом за раунд — город уничтожен; −5 экологии за удар; события с автором (для журнала), но **без автора в наблюдении** |
| `sanctions` | −5 развития всем неуничтоженным городам цели за каждую санкцию; цель видит автора |
| `clamp` | Экология 0..100, развитие ≥ 0 |
| `life_level`, `income` | Готовы со спринта 1 |
| `laugh` | +20 стране из `HostInput.laugh_winner` |
| `end_of_round` | Бомбы и помощь становятся доступными, санкции сбрасываются, `round += 1` |

**Наблюдения и действия:**
- `observe(state, country_id) -> Observation`: своё полностью; у чужих — уровни жизни городов, средний уровень жизни, уничтоженные города, коэффициент смеха; экология; кто наложил санкции на меня. Чужие бюджеты, арсеналы и авторы ударов **не видны**.
- `legal_actions(state, country_id, rules) -> ActionSpace`: доступные действия, цели, лимиты и стоимость.
- `validate(orders, action_space)`: структурная проверка до движка (то же будет делать API).

**Агенты и runner:**
- Протокол `Agent` (`act(obs, legal) -> CountryOrders`), `ScriptedAgent` с заданными приказами по раундам.
- `run_game(rules, scenario, agents, seed) -> GameLog` и `replay(log, rules=None) -> GameLog`.
- `GameLog`: правила, сценарий, зерно, приказы по раундам, события, снимки состояния. Сериализация в JSON.
- CLI: `python -m arena.engine.play --scenario smolny` — партия в терминале, приказы вводятся по странам.

**Реплей Смольного:**
1. Из «Копии Координаторской» взять стартовое состояние → уже в `scenarios/smolny.yaml`.
2. Из таблицы ответов оцифровать приказы годов 1–3 в `tests/replays/smolny_2026.yaml`. Свободный текст («Плюс ещё щит Исфахан и Йезд») переводится в структуру руками; спорные места — комментариями в файле.
3. Прогнать `replay` и сравнить с координаторской таблицей в состоянии «Раунд 4».
4. Расхождения записать в `docs/rules/smolny-replay-report.md`: где ошибся движок (чинить), где ошибались координаторы (фиксировать), где правила неоднозначны (решение в changelog).

### Тесты спринта

| Файл | Что проверяет |
|---|---|
| `tests/unit/systems/test_*.py` | Каждая система, включая все крайние случаи из таблицы выше |
| `tests/unit/test_observe.py` | **Секретность:** в наблюдении нет чужих бюджетов, бомб и авторов ударов |

## 9. Спринт 3. Симулятор и боты

**Цель:** проверять правила на тысячах партий уже сейчас.

### Боты (`arena/agents/bots.py`)

| Бот | Поведение |
|---|---|
| `RandomBot` | Случайные допустимые действия в пределах бюджета |
| `EconomistBot` | Инвестирует в города с наибольшей отдачей, щиты при угрозе |
| `EcologistBot` | Экопрограммы при экологии < 70, остальное — в развитие |
| `AggressorBot` | Технология → бомбы → удары по лидеру по уровню жизни |
| `AvengerBot` | Мирный, пока его не атаковали санкциями; отвечает санкциями и ядеркой тому, кого подозревает |

Боты получают только `Observation` и `ActionSpace` — так же, как будут получать LLM-агенты.

### Симулятор (`arena/sim/`)

- `run_batch(rules, scenario, lineup, seeds) -> list[GameLog]` с `multiprocessing`.
- Составы: все одинаковые, смешанные, случайные по странам.
- Метрики партии: победитель, раунд падения экологии ниже 30%, уничтоженные города, итоговые средние уровни жизни, доля отклонённых приказов.
- Результаты → Parquet в `data/sim/` (в `.gitignore`), сводка в терминале.
- `compare(rules_a, rules_b, seeds)` — одинаковые зёрна, отчёт о различиях метрик.

### Golden-тесты

- 5–10 фиксированных партий (сценарий + состав ботов + зерно) → снимки `GameLog` в `tests/golden/`.
- `just golden-update` обновляет снимки после осознанного изменения правил.

### Команды

```make
sim rules="v1.0" scenario="smolny" n="1000":
    cd backend && uv run python -m arena.sim --rules {{rules}} --scenario {{scenario}} --games {{n}}

rules-diff a b n="500":
    cd backend && uv run python -m arena.sim.compare --a {{a}} --b {{b}} --games {{n}}

golden-update:
    cd backend && uv run pytest tests/golden --update-golden
```

### Первое исследование

Ноутбук `analytics/notebooks/01_v1_balance.ipynb`: воспроизводит ли v1.0 коллапс экологии из Смольного? Какой бот чаще побеждает? Выводы — в `docs/rules/v1-balance-notes.md`. Это же — первые аргументы для v2.

### Критерий готовности

`just sim n=1000` отрабатывает примерно за минуту и печатает отчёт; golden-тесты в CI.

## 10. Спринт 4. Бэкенд

**Цель:** игру можно провести целиком через Swagger UI.

### Задачи

1. Зависимости: `fastapi`, `uvicorn[standard]`, `sqlalchemy[asyncio]`, `asyncpg`, `alembic`, `pydantic-settings`, `pyjwt`; dev: `httpx`, `testcontainers[postgres]`, `pytest-asyncio`.
2. Postgres локально: `compose.yaml` пока только с сервисом `db`.
3. `arena/main.py`: приложение, lifespan, `/healthz`, `/readyz`; `arena/settings.py` на `pydantic-settings`.

   - боты: если страной управляет бот, его приказы запрашиваются при подведении раунда.
6. API (`arena/api/`):

| Метод и путь | Роль | Назначение |
|---|---|---|
| `POST /api/games` | Ведущий | Создать игру: версия правил, сценарий, зерно, переопределения |

| `POST /api/auth/join` | Все | Код → cookie с JWT |
| `GET /api/games/{id}/observation` | Игрок | Наблюдение своей страны |
| `GET /api/games/{id}/action-space` | Игрок | Доступные действия и цены |
| `PUT /api/games/{id}/rounds/{n}/orders` | Игрок | Отправить или изменить приказ до закрытия фазы |
| `GET /api/games/{id}/world` | Все | Публичная сводка мира |
| `POST /api/games/{id}/phase` | Ведущий | Сменить фазу |
| `POST /api/games/{id}/rounds/{n}/resolve` | Ведущий | Подвести итоги |
| `POST /api/games/{id}/rounds/{n}/laugh` | Ведущий | Выбрать самую смешную команду |
| `GET /api/games/{id}/host/state` | Ведущий | Полное состояние и все приказы |

### Тесты

API-тесты с настоящим Postgres (testcontainers): права ролей, **секретность наблюдений через API**, идемпотентность подведения раунда (два одновременных запроса — один пересчёт), отклонение недопустимых приказов.

## 15. Как работать с Claude в новых диалогах

### Правила работы

- **Один спринт — один диалог** (большие спринты 1, 2, 4, 5 можно разбить на 2–3 диалога по блокам задач).
- В начале диалога приложи файлы из списка ниже и напиши, какой спринт и какие задачи из него делаем.
- Проси **готовые к запуску файлы** целиком (с путями в репозитории), а не фрагменты.
- После каждого блока — запуск тестов у себя (`just test`), вывод ошибок — обратно в диалог.
- В конце диалога попроси обновить **журнал прогресса** (раздел 16) и сохрани новую версию `DEV_PLAN.md`.
- Если в ходе работы меняется архитектурное решение — отдельный ADR в `docs/adr/`.

### Какие файлы прикладывать

| Когда | Файлы |
|---|---|
| **Всегда** | `DEV_PLAN.md` (с актуальным журналом прогресса), `ROADMAP.md`, `GAME_RULES.md` |
| **Спринты 1–3** | + текущие версии файлов движка, с которыми работаем (или архив `backend/arena/engine`) |
| **Спринт 2 (реплей Смольного)** | + `Копия Координаторская Смольный.xlsx` (старт), `Координаторская Смольный.xlsx` (итог раунда 4), `Немодель в Смольном _ Мировая Арена (Ответы).xlsx` (приказы), `таблица действий Смольный.xlsx` |
| **Спринты 4–7** | + ключевые файлы бэкенда/фронтенда по задаче; вывод ошибок и тестов |
| **Трек правил v2** | + `GAME_RULES_2.md` |
| **Трек правил v3** | + `GAME_RULES_2.md`, `GAME_RULES_3.md` |

Файлы стран (`Россия Мировая Арена…xlsx` и т.п.) нужны только как образец интерфейса и источник фото городов, презентация — как образец брифинга игроков. Для разработки их прикладывать не нужно.
