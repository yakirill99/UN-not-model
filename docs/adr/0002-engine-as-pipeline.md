# 0002. Движок как конвейер систем

- **Статус:** принято
- **Дата:** 2026-09-28

## Контекст

Правила будут меняться после каждой реальной партии (v1 → v2 → v3): добавляются устойчивость, рейтинг, резолюции ООН, экономика, кризисы. Одна большая функция подсчёта раунда сделает каждое изменение дорогим и опасным.

## Решение

`resolve_round(state, orders, rules, seed)` — чистая функция, которая прогоняет состояние через список систем. Каждая механика — отдельная система с интерфейсом `apply(state, orders, ctx) -> events`. Порядок систем задаётся в конфиге правил (`pipeline`). Случайность — только через `RngFactory` с отдельным потоком на систему. Любой игрок (человек, бот, RL, LLM) работает через протокол `Agent` с одинаковыми `Observation` и `ActionSpace`.

## Последствия

- Новая версия правил = новые системы + новый список `pipeline`; старые системы не трогаются.
- Детерминизм делает возможными golden-тесты, реплеи и честную оценку агентов.
- Правила секретности реализованы в одном месте (`observe`).
- Требуется дисциплина: никакой игровой логики в API и никаких `random` вне `RngFactory`.

## Рассмотренные альтернативы

- Одна функция с ветвлениями по версиям — быстро на старте, дорого с v2.
- ECS-фреймворк — избыточно для пошаговой игры с 20 городами.
