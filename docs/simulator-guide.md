# Симулятор: как он устроен и как читать его отчёт

Справка по состоянию на конец задачи #30 (спринт 3). Что такое `just sim`, что крутится под ним, откуда берутся правила и сценарии, что значат строки отчёта, и что показали четыре первые симуляции.

---

## 1. Что такое симуляция

Симуляция — это **партия «Мировой Арены», сыгранная ботами без людей и без сервера**. Тот же движок, те же правила из YAML, те же шесть раундов, что будут у живых команд; только вместо делегаций приказы подают скриптовые боты. Тысяча таких партий за полторы секунды даёт статистику, которую живыми играми не набрать никогда: кто побеждает, как часто мир доходит до ядерной зимы, на каком раунде, сколько городов гибнет. Именно так проверяются правила **до** того, как их увидят игроки, и именно так v1.0 будут сравнивать с v2.0.

## 2. Что крутится под капотом

```text
just sim 1000 smolny v1.0 mixed
  └─ python -m arena.sim                   CLI: аргументы → GameSpec'и → батч → отчёт → Parquet
       └─ arena/sim/batch.py               run_batch: партии в параллельных процессах
            └─ arena/engine/runner.py      run_game: 6 раундов, GameLog
                 ├─ arena/agents/bots.py   боты: Observation + ActionSpace → CountryOrders
                 └─ arena/engine/pipeline.py  resolve_round: конвейер систем из rules/*.yaml
                      └─ arena/engine/systems/*   budget → aid → build → develop → strikes → …
       └─ arena/sim/metrics.py             метрики одной партии и сводка по батчу
```

Пошагово, что происходит на `just sim 1000`:

1. **`specs_for`** строит 1000 спецификаций партии — `GameSpec(rules, scenario, seed, lineup)`. Сиды 0…999. Для состава `mixed` пятёрка ботов перемешивается по сиду и раздаётся странам.
2. **`run_batch`** раскладывает спецификации по процессам (`ProcessPoolExecutor`, по числу ядер) — на 12 ядрах тысяча партий идёт полторы секунды.
3. Каждый процесс для своей спеки делает **`run_one`**: грузит правила и сценарий, создаёт ботов (у каждого свой сид `seed·100 + i`) и вызывает **`run_game`**.
4. **`run_game`** играет 6 раундов. В каждом: каждому боту отдаётся `Observation` (что его страна видит по правилам секретности) и `ActionSpace` (что она может), бот возвращает `CountryOrders`; затем `resolve_round` прогоняет приказы всех через конвейер систем и выдаёт новое состояние и события. Всё пишется в `GameLog`.
5. **`metrics_of`** сжимает `GameLog` в строку метрик, **`summarize`** сводит тысячу строк в таблицу, которую вы видите; строки уходят в `data/sim/*.parquet` для ноутбуков.

Партия **полностью определяется спецификацией**: два прогона одной спеки дают одно и то же состояние (это проверяет тест). Отсюда следствие, важное для чтения результатов, — см. §6.

## 3. Где задаются правила и сценарии

Правила и стартовые условия — разные вещи и лежат в разных файлах.

**`rules/v1.0.yaml` — правила игры.** Единственное место, где живут числа: цены действий, эффекты (+15 п.п. за инвестицию, −5 экологии за удар), лимиты (3 бомбы за раунд), веса уровня жизни, коэффициенты дохода, порядок систем в раунде (`pipeline`). В Python-коде движка чисел нет; изменить цену экопрограммы — значит поправить YAML, и симулятор покажет, что изменилось. Новая версия правил описывает только отличия через `extends: v1.0`.

**`scenarios/*.yaml` — с чего стартует мир.** Страны, города, бюджеты, стартовое развитие, экология. Правила одни, а стартов может быть много. Сейчас их два, и они **сознательно разные** (решение 1 в §17 `GAME_RULES.md`):

| | `smolny` | `equal` |
|---|---|---|
| Что это | Исторический старт из координаторской таблицы реальной игры в Смольном 28.03.2026 | Соревновательный старт из методички |
| Развитие | Асимметрия: Россия 475 % (Екатеринбург 200 %), Франция 385 %, США 270 %, Иран 205 %, КНДР 165 % | 240 % у всех (60 % на город) |
| Бюджет | Россия 1445 $, США 1520 $, Иран 1055 $, Франция 985 $, КНДР 865 $ | 1000 $ у всех |
| Особенности | КНДР стартует с ядерной технологией (установлено реплеем, см. `smolny-replay-report.md`) | Ни у кого нет технологии |
| Зачем | Реплей реальной партии; «а что было бы, если…» | Честная проверка баланса: если здесь кто-то побеждает чаще, виноваты правила, а не стартовые условия |

`smolny` показывает, как правила ведут себя на неравном старте, `equal` — как на равном. Победа России в 34 % партий на `equal` при 20 % «по справедливости» — уже вопрос к правилам, а не к сценарию (см. §5).

## 4. Что значат строки отчёта

Заголовок: `1000 games, rules v1.0, scenario smolny, lineup mixed: 1.5s` — сколько партий, какие правила, какой старт, какой состав, сколько секунд.

| Строка | Что это | Как читать |
|---|---|---|
| `games` | Число сыгранных партий | При 200 партиях погрешность долей ≈ ±3–4 п.п.; при 1000 ≈ ±1,5 |
| `win_rate_by_bot` | Доля побед каждого типа бота среди партий, где он участвовал | Победитель — страна с наибольшим **средним уровнем жизни** после 6 раундов (§4.4 правил). Если один тип бота побеждает намного чаще 20 %, правила вознаграждают его стратегию |
| `win_rate_by_country` | Доля побед каждой страны | Сравнивать с 0,2. На `equal` отклонения — свойство правил; на `smolny` — ещё и стартовой асимметрии |
| `mean_final_ecology` | Средняя мировая экология после 6 раундов, % | Старт 100. Каждая технология, бомба и удар — −5; экопрограмма +30 |
| `ecology_collapse_share` | Доля партий, где экология хотя бы раз опустилась ниже 30 % | Порог «коллапса» задан в `metrics.py` (`ECOLOGY_COLLAPSE = 30`) |
| `mean_collapse_round` | Средний раунд, на котором это случилось (среди партий с коллапсом) | Раньше — хуже: значит, мир умирает до конца игры |
| `mean_cities_destroyed` | Среднее число уничтоженных городов из 20 | Уничтоженный город — развитие 0, уровень жизни 0, дохода нет |
| `mean_strikes` | Среднее число ядерных ударов за партию (включая поглощённые щитами) | |
| `mean_tech_countries` | Сколько стран из 5 к концу владеют ядерной технологией | 5 = все вооружились |
| `rejected_order_share` | Доля отклонённых движком единиц приказов | 0 у ботов — они строят приказ через `Planner`, который не даёт заказать неоплачиваемое. У людей будет > 0: это мера того, насколько форма приказов понятна |
| `mean_winner_life` | Средний уровень жизни победителя, % | Показывает «цену» победы: 55 % — победа в живом мире, 5 % — победа на пепелище |

## 5. Четыре первые симуляции — что каждая показала

### 5.1. `just sim 1000` — смешанные составы, старт Смольного

Базовый замер v1.0. В каждой партии пять разных ботов, распределённых по странам случайно.

```text
win_rate_by_bot   aggressor 0.53  economist 0.30  random 0.08  avenger 0.08  ecologist 0.00
mean_final_ecology 60   collapse_share 0.10 (раунд 5.8)   cities_destroyed 8.3   strikes 12.9
```

**Вывод:** правила v1.0 вознаграждают агрессию — Aggressor побеждает в половине партий при «справедливых» 20 %. Экология к концу теряет 40 п.п., в среднем гибнет 8 городов из 20. Ecologist не побеждает никогда: экопрограмма (200 $, +30 экологии **всему миру**) — общественное благо, платит один, выигрывают все, и по формуле уровня жизни это никогда не окупается для плательщика. Это первый количественный аргумент для v2 (устойчивость, рейтинг, ООН).

### 5.2. `just sim 200 equal` — смешанные составы, равный старт

Та же пятёрка ботов на 240 % у всех.

```text
win_rate_by_bot   economist 0.64  aggressor 0.18  random 0.16  avenger 0.03  ecologist 0.00
win_rate_by_country  russia 0.34 (!)   ecology 51   collapse 0.19
```

**Вывод:** без стартового преимущества Aggressor проигрывает Economist — на равном старте ядерная программа (500 + 150·n) отнимает те самые деньги, что дали бы +15 п.п. за инвестицию. А вот **Россия побеждает в 34 % партий при одинаковых стартах** — это уже не сценарий, а правила и порядок обработки: страны обрабатываются в порядке сценария, и первая по списку получает выгоду там, где важна очередность (например, удары в одном раунде по одному городу). Это надо проверить отдельно и, вероятно, перемешивать порядок стран по сиду.

### 5.3. `just sim 200 smolny v1.0 aggressor` — все пятеро агрессоры

```text
win_rate_by_country  france 1.0   ecology 0   collapse 1.0 (раунд 2)   cities_destroyed 14   strikes 37   tech 5
mean_winner_life 5.36
```

**Вывод:** ядерная война всех против всех. Экология в ноль ко второму раунду, 14 городов из 20 уничтожены, победитель — с уровнем жизни 5 %. Побеждает Франция: все бьют по лидеру, лидер на старте — Россия, её сносят первой, а Франция как вторая по силе успевает больше, чем другие. Обратите внимание на `1.0` во всех долях — об этом §6.

### 5.4. `just sim 100 smolny v1.0 economist,economist,economist,economist,aggressor` — четыре мирных, один агрессор

Состав задаётся в порядке стран сценария (Россия, США, Франция, Иран, КНДР), так что агрессор здесь — КНДР.

```text
win_rate_by_bot  economist 1.0  aggressor 0.0     win_rate_by_country  iran 1.0
ecology 0   collapse 1.0 (раунд 3)   cities_destroyed 7   strikes 12   tech 1
```

**Вывод:** один агрессор среди мирных **не побеждает** — он тратит на ядерную программу, а санкции и удары не компенсируют отставание в развитии. Но он один обрушивает мир: 12 ударов, 7 городов, экология 0 к третьему раунду. Экономисты после первого удара ставят щиты (они видят новости, но не арсеналы), поэтому дальше страдают меньше. Победил Иран — тот, кого агрессор бил меньше (агрессор бьёт лидера, а лидер на старте Смольного — Россия).

## 6. Почему в 5.3 и 5.4 все доли ровно 1.0

Потому что это **одна и та же партия, сыгранная 200 раз**. Партия определяется спецификацией; из четырёх ботов случайность есть только у `RandomBot`, а из систем движка ни одна пока не тянет случайные числа (`RngFactory` заведён под события v2). Значит, при фиксированном составе без `random` сид ничего не меняет — все 200 партий идентичны. Разнообразие в `mixed` даёт только перестановка ботов по странам.

Это не ошибка, но ограничение, которое надо помнить: **для фиксированного состава достаточно одной партии**, а статистика возникает либо от `mixed`, либо от `random` в составе, либо после появления случайных событий в v2. Задача #33 (исследование баланса) должна это учитывать; вероятно, добавим ботам небольшой сидированный шум в выборе целей.

## 7. Как проходит симулированная партия и от чего мы абстрагировались

Реальный год «Мировой Арены» — это новости, дебаты, закулисные переговоры и только потом тайные приказы. В симуляции есть **только приказы и их резолюция**. Переговоров нет, договорённостей нет, ООН нет — не потому что это неважно, а потому что:

- в v1.0 переговоры **не имеют механики**: они происходят между людьми словами и влияют только на то, какие приказы люди подадут; движку нечего моделировать. Механики появятся в v2 (резолюции ООН, голосования, рейтинг) — тогда в `Agent` добавятся `vote()` и `negotiate()`, они уже предусмотрены в `ROADMAP` §3.5;
- ведущий тоже отсутствует: коэффициент смеха никому не начисляется (`HostInput.laugh_winner = None`). Если это заметно влияет на баланс, в #33 добавим «ведущего-бота», выбирающего случайную команду.

Что боты видят и как решают — ровно то же, что увидят люди и LLM-агенты: `Observation` (своё полностью; у чужих — уровни жизни, уничтоженные города, смех; экология; новости прошлого раунда без авторов ударов) и `ActionSpace` (доступные действия с целями, лимитами и ценами). Бот **физически не может** подсмотреть чужой бюджет или арсенал — в его входных данных таких полей нет.

### Роли ботов

| Бот | Стратегия | Что видит и на что реагирует |
|---|---|---|
| `economist` | Все деньги в инвестиции, по кругу от самого слабого города | Как только в новостях появились удары или уничтоженные города — ставит щиты на два незащищённых города, потом инвестирует |
| `ecologist` | Как economist, но при экологии < 70 % сначала две экопрограммы | Мировая экология |
| `aggressor` | Санкции лидеру; технология → до 3 бомб за раунд → удары по лучшим городам лидера; один щит; остаток в развитие | Лидер = чужая страна с наибольшим средним уровнем жизни |
| `avenger` | Мирный economist, пока его не трогают. Санкции в ответ тем, кто санкционировал его. После удара по своему городу — ядерная программа против подозреваемого | Помнит санкционеров (жертве авторы санкций видны). Удар анонимен — винит последнего санкционера, а если таких нет — лидера |
| `random` | Случайные допустимые действия в пределах бюджета | Сид; нулевая модель для сравнения |
| `idle` | Ничего не делает | Базовая линия: столько даёт «просто сидеть» |

Роли не рандомны и не «по сценариям» — это фиксированные стратегии, написанные вручную в `arena/agents/bots.py`. Их цель — не изображать людей, а натягивать правила в разных направлениях: что будет, если все воюют; если все копят; если один воюет среди мирных.

## 8. Что осталось до первой рабочей версии (v1.0 на живой партии)

Сделано: спринты 0–2 полностью (движок, правила, все системы, наблюдение, реплей Смольного) и половина спринта 3 (боты, симулятор).

| Спринт | Что | Зачем для первой партии |
|---|---|---|
| 3 (остаток) | #31 `compare` двух версий правил; #32 golden-партии с ботами в CI; #33 исследование баланса → `v1-balance-notes.md` | Заморозить поведение движка снимками и понять, что именно чинить в v2 |
| 4. Бэкенд | FastAPI + PostgreSQL: создать игру, коды команд, вход по коду, `observation` / `action-space` / `orders`, фазы, `resolve`, выбор смешной команды, панель ведущего | Партию можно провести через Swagger, состояние переживает перезапуск |
| 5. Фронтенд | Вход по коду, карточка страны из `Observation`, **форма приказов из `ActionSpace`** со счётчиком «потрачено / осталось», сводка мира, панель ведущего | Игроки и ведущий в браузере, с телефона |
| 6. Контейнеры | `Dockerfile`, `compose`, `just up` | Запуск на любом ПК с Docker за одну команду |
| 7. Реалтайм и сдача | WebSocket (кто отправил приказ, смена фазы без F5), Playtest, живая партия, тег `v1.0` | Первая настоящая игра на движке |

Чего в этом списке **нет** и не будет в v1.0: переговоров, ООН, случайных событий, LLM-агентов — это v2/v3 (`ROADMAP`). v1.0 — это ровно правила Смольного, только с автоматическим подсчётом, приоритетной оплатой, секретностью «по построению» и журналом событий вместо координаторской таблицы.

## 9. Шпаргалка

```bash
just sim                                   # 1000 партий, smolny, v1.0, mixed
just sim 200 equal                         # равный старт
just sim 200 smolny v1.0 aggressor         # один бот у всех (одна партия ×200 — см. §6)
just sim 100 smolny v1.0 economist,economist,economist,economist,aggressor   # состав по странам
uv run --directory backend python -m arena.sim --games 500 --scenario equal --lineup mixed --workers 4 --no-save
uv run --directory backend python -m arena.engine.play --scenario smolny --seed 1   # одна партия с печатью по раундам
```

Результаты: `data/sim/<rules>_<scenario>_<lineup>_<n>.parquet` (не в git). Колонки — метрики из §4 плюс `seed`, `lineup` и `final_life` (JSON-строки).
